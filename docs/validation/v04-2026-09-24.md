# V04 local security review — 2026-09-24

Scope: the single-worker, loopback-bound VigilVoice presentation stack. Review and tests used the isolated `vv-s02-db`/`vv-v04-backend` stack, not the existing demo database. Tested Python 3.11 image: `sha256:b2543871eefbf2ff2461fb45c15e6f23339f99aa85dd84e0245813b124eee04f`. HEAD was `58f7e32`; the worktree is dirty, so the image and file hashes below identify this checkpoint, not a release freeze.

| Check | Result |
|---|---|
| Session/verifier separation | Session bearer hashes are looked up by session/action ownership; the demo inbox requires a distinct `X-Demo-Verifier-Key`. Wrong-session access, wrong-action approval, replay, three-attempt lockout, expiry, HIGH retention and audit rollback passed the live API suite. The verifier is still a separate *demo role*, not independent identity proof. |
| Unauthenticated admission | `POST /sessions` now admits at most 60 creations per rolling minute per process and returns 429 with `Retry-After: 60`. Live loopback check: 60 created, next 5 rejected. At most eight WebSockets can wait for their first credential frame; the ninth closed with code 1013, and subsequent authenticated streaming passed. Both limits are single-process controls, not distributed DoS protection. |
| SQL and input/output | Reviewed routes, SQL and browser rendering. SQL values are bound parameters; fixed query suffixes only select `FOR UPDATE`. Pydantic bounds action/OTP inputs, upload bytes/time and WAV format are checked, first WebSocket text frame is length-limited, sequenced PCM frames are fixed-size. Browser uses `textContent` for untrusted payloads; HTTP responses set no-store, nosniff, no-referrer and CSP. No dynamic HTML insertion or application log calls were found in `app/`. This is source review, not a penetration test. |
| Secrets and retained data | No raw audio column or raw-audio application logging was found. Session/approval tokens and OTP codes are stored as hashes; the plaintext demo OTP lives only in the process inbox until expiry/confirmation/block/restart. Sample Uvicorn access logs showed paths/statuses, not headers or bodies. PostgreSQL retains session metadata, scores, action payloads (including recipient) and audit records indefinitely; there is no retention/deletion policy. This needs a policy before handling real personal data. The UI keeps its session token in page memory, not local storage. |
| Dependencies | `uvx pip-audit -r requirements.txt --no-deps --disable-pip` (pip-audit 2.10.1, online PyPI advisory source) reported **no known vulnerabilities** for the 28 pinned packages at this check. It warned that pins lack hashes. This is point-in-time advisory coverage, not a supply-chain guarantee or an OS/image scan. |
